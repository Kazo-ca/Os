# Changelog

The changes of Kazo OS, by version. This file is generated from `wasm2/KazoOs/changes/` by
`wasm2/KazoOs/build/tools/collect-changes.sh` (ADR 0186): do not edit it by hand. Changes already
deployed but not released yet are in the Settings ▸ What's new page of the OS.

## 3.6.0 (2026-11-24)

### For developers

- **Test an app on a phone on the published trimmed OS.** The shared app test harness (build/app-e2e) also installs and opens an app in the mobile shell, through its app drawer and Terminal. Its SHELLS export tells an app's tests that this version supports phones (ADR 0281). ([app-repository.md](doc/en/wasm/framework/app-repository.md))

## 3.5.2 (2026-11-18)

### Improved

- **The kazowebd web server is a manual service.** kazowebd no longer starts on its own at the login. An administrator starts it with systemctl start kazowebd or from Web Server Manager, or makes it start at every login with systemctl enable kazowebd (ADR 0286). ([static-sites.md](doc/en/wasm/dev/static-sites.md))

### Fixed

- **The automatic services of a feature start at the login.** In Kazo OS 3.5.1, an automatic service started at the login only if its code was already loaded, so the service of a feature stayed inactive (dead) until another entry point of the feature was launched. The OS now starts every enabled automatic service at the login and loads only the code of the services that start. An entry point of a feature may also start, stop and set the start mode of a service of its own feature (ADR 0286). ([github.com/Kazo-ca/Os/issues/625](https://github.com/Kazo-ca/Os/issues/625))

### For developers

- **Test an app on the published trimmed OS.** build/app-e2e/ holds a shared harness and a short test (smoke.mjs) that serve the published trimmed OS, install the app with kazopkg as the Store does, launch it and fail on a missing member, a kazopkg refusal or the app's failure panel. App repositories reach it through their Kazo OS submodule (ADR 0281). ([app-repository.md](doc/en/wasm/framework/app-repository.md))

## 3.5.1 (2026-11-17)

### New

- **The connect dialog names the server a provider will reach.** When a drive type marks a field as the server address (ADR 0284), Connect a network drive writes "This provider will reach <host>." before saving, and refuses an address the OS cannot allow (http, a user name or password in the URL, an IP address, localhost) with the reason. KazoNetworkDriveField.IsServerAddress tells apps which field it is. ([cloud-drives-ui.md](doc/en/wasm/dev/cloud-drives-ui.md))

### Fixed

- **The commands and windows of a feature start again.** In Kazo OS 3.5.0, no entry point of a feature could start: help listed its command, but running it answered command not found, and its windows did not open. The OS now finds an entry point together with its feature, without loading the other entry points of the feature. ([github.com/Kazo-ca/Os/issues/621](https://github.com/Kazo-ca/Os/issues/621))

## 3.5.0 (2026-11-17)

### New

- **Features can declare roles that an administrator grants.** A feature can now declare roles, such as the manager of its virtual machines, and reserve some of its commands and windows for them. An administrator grants a role to an ordinary account in the new Roles of the features panel of Settings ▸ Users, or with sudo kazorole grant <user> <role>; kazorole list shows who holds what. Every administrator holds every role, implicitly. A command that requires a role you do not hold is absent from the launcher and the completion, and the shell answers role required (exit 126). Each sensitive operation still asks the system’s own window for your password, never the feature’s, and auth.log records feature.authenticate, feature.role-denied, role.grant and role.revoke. A feature’s roles are named <feature>:<role>, such as x86:vm-manager. For developers: FeatureDefinition.Roles, FeatureEntryPoint.RequiresRole, KazoUser.Current.IsInRole (the OS role admin, or <feature>:<role>), KazoRoles, KazoFeatureAuthentication (AuthenticateAsync, ConsumeAsync), KazoUserAccounts.ListRolesAsync, GrantRoleAsync and RevokeRoleAsync. ([0247-feature-declared-roles.md](doc/en/wasm/dev/adr/0247-feature-declared-roles.md), [0283-feature-roles-isinrole-adjustments.md](doc/en/wasm/dev/adr/0283-feature-roles-isinrole-adjustments.md))
- **Features declare their own permissions, and no permission is granted silently any more.** An optional feature of the OS can now declare permissions of its own under a reserved prefix (for example x86.vm.use or x86.vm.destroy), normal or dangerous, with a title and a risk statement. An app that uses the feature asks for them in its manifest; a normal one is granted while the feature is installed and enabled, a dangerous one only after an administrator approves it, always in the OS’s secure window, even from a terminal command. A permission can cover others. At sign-in the OS now grants only the capabilities it knows: an unknown identifier is never granted and is written to /var/log/syslog, and the bus topic permissions need an approval (issue #432). Settings ▸ Permissions, the installation approval window and kazopkg show the feature that declares a permission. For developers: FeatureDefinition.CapabilityPrefix and ProvidedCapabilities, IFeatureServiceContext.Caller.Require and Has, ICapabilityCatalog. ([0246-provider-declared-permissions.md](doc/en/wasm/dev/adr/0246-provider-declared-permissions.md))
- **Installing an app installs what it needs, with one approval.** When an app needs another package, for example a feature of the OS, the Kazo OS Store and kazopkg now install it with the app: they show the whole plan first (each package, its version, its size and its dangerous permissions) and ask once. A feature always goes to every user, so an administrator approves it, even for an app installed for yourself; if no administrator approves, nothing is installed. A required package that no catalog publishes stops the installation with its name and the versions it needs. The app's page in the Store lists what it needs and whether it is installed, and warns when the installed version is out of range. Removing a package other apps need names them and disables them; their data stays, and installing the package again turns them back on. An update that would break an installed app is refused. kazopkg install, remove and update ask for a confirmation; --yes answers for you. For developers: KazoApps.RequestInstallAsync opens the Store on an optional dependency; KazoAppPackages.PlanInstallAsync and GetDependentsAsync; catalog.json lists the dependencies of each version. ([0248-store-and-kazopkg-dependency-resolution.md](doc/en/wasm/dev/adr/0248-store-and-kazopkg-dependency-resolution.md))
- **Kazo OS tells you when the browser erased its data, and can ask it not to.** Browsers may erase a site's data when the disk is full or after a while without a visit. Kazo OS now notices it at startup: the first-run screen says the browser erased its data, with the date of the last start and how to restore a backup, and kern.log gets storage.evicted. The new Settings ▸ System ▸ Storage page shows how much the browser lets Kazo OS use, how much each kind of storage takes when the browser tells, whether the storage is protected, with a button to ask the browser to protect it, and the space each feature declared. A feature that keeps disks in the browser (a virtual machine, for example) is told when they were erased, and you get a notification. df shows a /dev/feature/<id> line for each such feature. For developers: KazoStorage (GetEstimateAsync, RequestPersistenceAsync, RegisterMarkerAsync, ReportUsageAsync, GetFeatureUsageAsync, Changed). ([0250-storage-persistence-and-eviction.md](doc/en/wasm/dev/adr/0250-storage-persistence-and-eviction.md))
- **Network drive types are described by the OS.** The Connect a network drive dialog, Settings > Cloud accounts and mount -t now show every network drive type the OS describes, including those a Store feature provides, marked "Provided by <feature>". S3 uses the same generic form, and its access key id is now a masked secret. mount never reads a secret from the command line. A drive whose provider is missing stays greyed in File Explorer with the reason, and Install the provider opens the Store. Apps read the descriptions with KazoDriveInfo.DescribeNetworkDriveTypesAsync and GetProviderMissingDrivesAsync. ([cloud-drives-ui.md](doc/en/wasm/dev/cloud-drives-ui.md), [drive-providers.md](doc/en/wasm/framework/drive-providers.md))
- **Privacy policy and terms of use, linked from sign-in and About.** The privacy policy and the terms of use say who publishes Kazo OS, what stays in the browser, what cloud providers, the Store, AI services and the site's hosts receive, and how to reach us. The sign-in screen and Settings ▸ About link to them in the language of the session. ([legal-pages.md](doc/en/wasm/dev/legal-pages.md))

### Improved

- **The Roboto font comes from Kazo OS itself, not Google Fonts.** Kazo OS now serves the Roboto font with its own files, so opening it no longer sends your address to Google Fonts and the font also works offline. The privacy policy says so. ([legal-pages.md](doc/en/wasm/dev/legal-pages.md))

### For developers

- **A developer kit for network drive providers.** dotnet new kazoos-drive-provider creates a feature that provides a network drive type, with tests that run the public conformance suite KazoDriveProviderTests against an in-memory service. A WebDAV sample shows a form connection. drives.provide alone now lets a provider reach the hosts of its declaration, and a form field marked serverAddress lets it reach the server each user types there while the drive is open. The approval screen names both. ([drive-providers.md](doc/en/wasm/framework/drive-providers.md), [0284-drive-provider-hosts-and-typed-server-address.md](doc/en/wasm/dev/adr/0284-drive-provider-hosts-and-typed-server-address.md))
- **An account of a declared drive type belongs to its feature.** Accounts of a drive type a feature declares now record that feature (CloudAccount.FeatureId). Another feature serving the same type later never reaches them: its drive context and a reconnection are refused, and signing in again creates a separate account. CloudAccountService.CreateDriveProviderContextAsync and SaveFormAccountAsync now take the feature id. ([cloud-accounts.md](doc/en/wasm/dev/cloud-accounts.md), [drive-providers.md](doc/en/wasm/framework/drive-providers.md))
- **Apps can reach the web services they declare directly.** KazoDirectHttpClient sends requests straight through the browser, without the Kazo server, and reads the response as a stream. An app needs the dangerous capability network.direct.access and lists every host it reaches in directNetworkHosts; the administrator approves that list, and the OS refuses any other host. ([sdk-network.md](doc/en/wasm/framework/sdk-network.md))
- **Drives of a removed or disabled provider are kept.** When the feature that provides a drive type is removed or disabled, its drives are unmounted but stay in the user's list with their mount point reserved, and come back by themselves when the same feature returns. Another feature that provides the same type does not take them over. Platform.Core: NetworkDrive.ProviderFeatureId; network-drives.json lines gain a provider field. ([network-drive-sources.md](doc/en/wasm/dev/network-drive-sources.md), [drive-providers.md](doc/en/wasm/framework/drive-providers.md))
- **Publish Kazo OS without Dropbox, OneDrive or S3.** The shipped cloud drive connectors moved to a new package, Kazo.Os.Platform.CloudDrives (same namespaces). The MSBuild properties KazoOsDropboxDrives, KazoOsOneDriveDrives and KazoOsS3Drives (true by default) leave a connector out of the build; with all three false the assembly leaves the download. KazoOs:CloudDrives:Disabled in appsettings.json and the disabled key of /etc/kazoos/cloud-drives.config hide a type without publishing again. A drive of a disabled type stays in the user's list, unmounted, and comes back when the type is enabled again. Breaking change for a host that composes the connectors itself: reference Kazo.Os.Platform.CloudDrives (ADR 0282 §5). ([cloud-drives.md](doc/en/wasm/dev/cloud-drives.md), [0282-third-party-drive-providers.md](doc/en/wasm/dev/adr/0282-third-party-drive-providers.md))
- **The OS opens the drive types that Store features provide.** A drive type a feature declares is offered as soon as the feature is installed and enabled, with no restart. Its provider is loaded at the first drive, once per page, in the feature's own process; a provider that fails or is slow leaves the drive disconnected with a line in the feature's log, and a login never waits for it. The installer refuses a second feature that provides the same type. ([drive-providers.md](doc/en/wasm/framework/drive-providers.md))
- **The OS signs in to the drive types features declare.** An OAuth drive type an installed feature declares is now signed in by the OS like Dropbox and OneDrive, with the same callback page and tokens sealed on the device; an administrator can replace its app ids in /etc/kazoos/cloud-drives.config. Form accounts keep their plain values and seal their secret ones, and a provider's context only reaches the access token or secrets of the drive it opens. Platform.Core: AppCatalog.GetDriveProviders, CloudAccountService.SaveFormAccountAsync and CreateDriveProviderContextAsync; CloudOAuthProvider.Identity is now optional (breaking for code that builds a CloudOAuthProvider). ([drive-providers.md](doc/en/wasm/framework/drive-providers.md), [cloud-accounts.md](doc/en/wasm/dev/cloud-accounts.md))
- **The SDK describes network drive providers.** A feature can now declare the network drive types it provides (FeatureDefinition.DriveProviders, the drives.provide capability) and write them with the new Kazo.Os.AppSdk.Drives contract: KazoDriveProvider, KazoDriveFolder, KazoDrivePath. The build checks the declaration (KOSAPP0036). ([drive-providers.md](doc/en/wasm/framework/drive-providers.md))

## 3.4.3 (2026-11-17)

### New

- **A network app knows whether the Kazo server's relay works.** KazoRealNetwork.GetRelayStateAsync tells an app holding network.real.access, without trying, whether the Kazo server's relay can carry its connections (no server, relay turned off, permission not received yet, ready with the blocked ports), and RelayStateChanged says when it changes. A failed connection now says why: KazoTcpClient and KazoUdpClient throw a KazoRelayException with the same SocketError as before, KazoHttp carries ERR_KAZO_RELAY_* codes, and curl, wget, cat and the Browser explain them (ADR 0278). ([sdk-network.md](doc/en/wasm/framework/sdk-network.md))

### Fixed

- **A warning when the browser storage is full.** Chromium no longer tells web pages how much space is really left, so Kazo OS now shows the "Low storage space" notification as soon as the browser refuses to save something, and frees the data of deleted files sooner to make room. ([github.com/Kazo-ca/Os/issues/493](https://github.com/Kazo-ca/Os/issues/493))
- **An app with only filesystem.private.* can create its ~/.config folder.** KazoDirectory.CreateDirectoryAsync no longer fails with CapabilityDenied on ~/.config when the app may create its own ~/.config/<appId>/ but not look at ~/.config. ([capabilities.md](doc/en/wasm/framework/capabilities.md))
- **An edit of apps.config made right after logging in is no longer missed.** Kazo OS now starts watching apps.config before reading it, so a change written while the session opens is always applied. ([github.com/Kazo-ca/Os/issues/493](https://github.com/Kazo-ca/Os/issues/493))
- **File dialogs no longer stop the desktop when closed right after entering a folder.** Opening a folder in an Open or Save dialog and confirming at once could show "An unhandled error has occurred" and leave every window unresponsive. The dialog now closes cleanly. ([github.com/Kazo-ca/Os/issues/519](https://github.com/Kazo-ca/Os/issues/519))
- **Installed apps show their icon before their first launch.** The OS now serves the icons of installed apps at boot and right after an install, so the launcher, the desktop and the Store no longer show a broken image until the app is opened once. ([app-installation.md](doc/en/wasm/dev/app-installation.md))
- **No network errors when Kazo OS starts offline.** With no network connection, Kazo OS no longer tries to check for a new version or refresh the app catalogs, so the browser console stays free of failed requests. ([github.com/Kazo-ca/Os/issues/493](https://github.com/Kazo-ca/Os/issues/493))
- **On mobile, the top of an app answers touches again.** The notification shade's handle now has a status-bar strip of its own above the open app, instead of covering the app's top buttons. ([mobile-home-screen.md](doc/en/wasm/dev/mobile-home-screen.md))
- **Screen readers and voice control name the taskbar, Start menu and Calculator keys by what they show.** The app launcher button, the taskbar clock, the Start menu apps and Quick access links, and the Calculator keys MC, MR, M+, M-, C, AC and x² now have accessible names that contain their visible text, so you can say what you see. ([github.com/Kazo-ca/Os/issues/493](https://github.com/Kazo-ca/Os/issues/493))
- **head ends on /dev/urandom and counts bytes with -c.** head now reads a file only as far as what it prints, so head -c 16 /dev/urandom ends instead of filling the tab's memory. -c counts bytes, as in Linux. ([linux-commands.md](doc/en/wasm/dev/linux-commands.md))

### For developers

- **A trimmed publish writes the API surface it ships.** A trimmed publish of a host now writes kazoos-api-surface.json.gz next to wwwroot/: every assembly it ships with its types, methods and fields, so an app can be checked against the trimmed OS before it is published (ADR 0277). ([trimmed-publish.md](doc/en/wasm/dev/trimmed-publish.md))
- **An app's build refuses APIs the trimmed OS removed.** KazoOsPack now checks the package against the API surface of the targeted Kazo OS, which Kazo.Os.App.Build brings: a call to a member the trimmed OS does not have fails the build with KOSAPP0100 and a replacement when one is known, instead of being refused at installation. KazoOsApiCheck=false turns it into the warning KOSAPP0101 (ADR 0277). ([app-repository.md](doc/en/wasm/framework/app-repository.md))

## 3.4.0 (2026-11-15)

### New

- **A beta of Kazo OS on os-beta.kazo.ca.** Prereleases of Kazo OS run on their own site, os-beta.kazo.ca (os.kazo.ca/beta leads there), with their own data. A beta shows a "Beta" badge next to its version and, in Settings > About, a link back to the stable version; the stable site offers a "Try the beta" link. ([beta-site.md](doc/en/wasm/dev/beta-site.md), [0271-beta-channel-and-automatic-app-updates.md](doc/en/wasm/dev/adr/0271-beta-channel-and-automatic-app-updates.md))
- **A welcome wizard at your first sign-in.** The first time you sign in, Kazo OS lets you choose your language, your theme, your wallpaper and your time zone before the desktop opens. Each choice applies at once, you can skip the wizard, and everything stays changeable in Settings. ([welcome-wizard.md](doc/en/wasm/dev/welcome-wizard.md))
- **Apps can carry their own libraries, and a shared library is loaded once.** An app installed from a package can now have libraries of its own (another project, a NuGet package or a DLL): KazoOsPack puts them in the package and the OS loads them before the app, so such an app is no longer refused for a missing assembly. A library its author marks as shared (MSBuild property KazoOsSharedLibrary in the library's project) is loaded once for every app: the copy of an installed feature, otherwise the newest one of the same major version. When another copy is already loaded, the app keeps running with it and is shown as “Restart to finish”. An app whose shared library has another major version than an installed feature's copy is refused at installation, as is a library named like an assembly of the OS. For developers: nothing to declare in the app; kazoos-package.json lists the libraries. ([0261-app-libraries-and-shared-versions.md](doc/en/wasm/dev/adr/0261-app-libraries-and-shared-versions.md))
- **Apps can use the services of an optional feature of the OS.** A feature can now provide services to other apps: it declares ProvidedServices (an interface of a shared library and the class that implements it), and an app gets the instance with KazoFeatures.GetServiceAsync<T>(), or null when the feature is absent, disabled or outside the version range the app declares. The instance is created once per page, on the first request, in the feature’s own context and with its permissions. KazoFeatures.IsAvailable<T>(), GetStatusAsync<T>() and Changed tell why and when a service comes and goes. An app that declares the feature as an optional dependency stays in the catalog when the installed version is out of range. The build checks the declaration (KOSAPP0035) and that an app calling KazoFeatures declares a dependency (KOSAPP0034); a second feature that provides the same contract is refused at installation. ([0262-feature-service-registry-and-async-resolution.md](doc/en/wasm/dev/adr/0262-feature-service-registry-and-async-resolution.md))
- **Connect a network drive from File Explorer, Settings or the terminal.** File Explorer's "Connect a network drive" dialog offers a folder of the computer and, once their connectors arrive, Dropbox, OneDrive and S3 compatible storage, with the choice between the whole storage and a folder reserved for Kazo OS. Settings ▸ Cloud accounts lists the accounts, reconnects and removes them. In the terminal, mount -t dropbox, onedrive or s3 mounts the same drives. Apps holding the new cloud-accounts.manage capability reach all of it through KazoCloudAccounts and KazoDriveInfo.MountNetworkDriveAsync. ([cloud-drives-ui.md](doc/en/wasm/dev/cloud-drives-ui.md), [0270-cloud-drives-in-the-app-sdk.md](doc/en/wasm/dev/adr/0270-cloud-drives-in-the-app-sdk.md))
- **Links to Kazo OS show an image on Facebook.** A link to os.kazo.ca shared on Facebook, LinkedIn or X now shows the Kazo OS image, its title and a short description. ([github-pages-deployment.md](doc/en/wasm/dev/github-pages-deployment.md))
- **Optional features of the OS, installed for the whole machine.** A package can now bring a feature (kind feature): one identity with its entry points (commands, windows, services), installed for every user by an administrator who approves its permissions once at installation; its entry points ask nothing at their first launch. The Store lists a feature its catalog marks kind: feature with the apps and offers “Install for everyone” only. Settings ▸ Applications lists each feature with its entry points. For developers: FeatureDefinition and FeatureEntryPoint in the SDK, one entrypoints/<suffix>.json per entry point in the package, diagnostics KOSAPP0032 and KOSAPP0033. ([0260-feature-app-type.md](doc/en/wasm/dev/adr/0260-feature-app-type.md))
- **Privacy policy and terms of use pages.** os.kazo.ca/privacy.html and os.kazo.ca/terms.html explain, in French and English, that Kazo OS has no server receiving your files or cloud tokens. They are plain pages, available offline. ([cloud-accounts.md](doc/en/wasm/dev/cloud-accounts.md))
- **S3 buckets as network drives.** A bucket of an S3 compatible service (Cloudflare R2, Backblaze B2, MinIO, AWS S3), or a prefix of it, mounts under /mnt as a network drive. Requests are signed in the OS with the user's keys, which stay sealed on the device in an s3 cloud account; folders are prefixes and writes are guarded by the ETag. The bucket needs a CORS rule for Kazo OS, described in the S3 guide. ([s3-drives.md](doc/en/wasm/dev/s3-drives.md), [0267-cloud-drives-as-network-drives.md](doc/en/wasm/dev/adr/0267-cloud-drives-as-network-drives.md))

### Improved

- **Installed apps keep a single copy of their files.** The files of an installed app are no longer copied into a browser cache in every session: the service worker serves them straight from the app's folder in the file system, after checking they are the files its manifest declares. A 64 MiB app with its previous version kept now takes 128 MiB instead of 192 MiB (236 MiB before file content was stored as binary), and its first launch in a session copies nothing. The OS database moves to version 6; a backup keeps the same format. ([0274-single-copy-of-app-files.md](doc/en/wasm/dev/adr/0274-single-copy-of-app-files.md), [app-installation.md](doc/en/wasm/dev/app-installation.md))
- **Large files are read as they are used.** Opening a file over 16 MiB no longer loads it whole: only the part being read is in memory, 16 MiB at most, and jumping ahead in a file loads only the piece around the new position. Apps read such a file asynchronously; a synchronous read past what is loaded is refused. ([kazo-file-api.md](doc/en/wasm/framework/kazo-file-api.md), [0275-partial-read-and-file-address.md](doc/en/wasm/dev/adr/0275-partial-read-and-file-address.md))
- **Large files save and open much faster.** File content is now stored as bytes instead of text, and each 256 KiB piece is checked by its own fingerprint when it is read. The first start after the update converts the files already stored once, behind a waiting screen; it resumes where it stopped if the tab is closed. ([browser-infrastructure.md](doc/en/wasm/dev/browser-infrastructure.md), [0272-binary-file-content.md](doc/en/wasm/dev/adr/0272-binary-file-content.md))
- **Network drives show their service and starting folder.** In the File Explorer, each cloud drive carries the Dropbox or Microsoft mark and a second line with the service and the starting folder, so two accounts with the same e-mail address are told apart. With the folder reserved for Kazo OS, the sign-in dialog shows where that folder is (/Apps/Kazo OS Folder/) before the starting folder. Apps read KazoDriveInfo.Root and KazoCloudProvider.AppFolderPath. ([cloud-drives-ui.md](doc/en/wasm/dev/cloud-drives-ui.md))
- **Saving a large file takes less memory.** A file larger than 16 MiB is now handed to the browser 16 MiB at a time while it is saved, instead of being copied whole in the OS memory, which WebAssembly never gives back. KazoFile.WriteAllBytesAsync no longer copies the array it receives: do not change it before the returned task completes. ([browser-infrastructure.md](doc/en/wasm/dev/browser-infrastructure.md), [0275-partial-read-and-file-address.md](doc/en/wasm/dev/adr/0275-partial-read-and-file-address.md))
- **Search and categories in the "Open with" box.** The File Explorer's "Open with" box now has a search box and a category selector to find an installed app quickly. Each app's id no longer spills below its row, on a computer as on a phone. ([file-explorer.md](doc/en/wasm/dev/file-explorer.md))
- **The Kazo OS Store moves to the Start menu's Quick access.** The Start menu's Quick access panel now lists File Explorer, the Store, then Settings. The Store is no longer pinned by default: a profile where it was pinned by default loses that pin once, and a pin you add back stays. ([app-installation.md](doc/en/wasm/dev/app-installation.md), [0268-store-in-start-menu-quick-access.md](doc/en/wasm/dev/adr/0268-store-in-start-menu-quick-access.md))
- **The Store offers the newest app version your Kazo OS runs, and a beta OS reads the beta catalog.** The Store, kazopkg and the update check no longer offer an app version built for a newer Kazo OS than yours: they pick the newest version that runs here, so an app rebuilt for a newer SDK does not block an older OS. A prerelease of Kazo OS reads the beta channel of the official catalog (catalog-beta.json) and offers the beta versions of the apps; a stable Kazo OS reads catalog.json and never sees them. ([app-installation.md](doc/en/wasm/dev/app-installation.md), [0271-beta-channel-and-automatic-app-updates.md](doc/en/wasm/dev/adr/0271-beta-channel-and-automatic-app-updates.md))

### Fixed

- **Connect a network drive: leave a sign-in that failed.** While the Dropbox or OneDrive sign-in window is open, the dialog says so, and Back, Close and Escape stay usable: they stop waiting for a window that shows an error or was closed, instead of leaving the dialog stuck. ([cloud-drives-ui.md](doc/en/wasm/dev/cloud-drives-ui.md))

- **Settings: aligned Server Connection form.** In Settings > Server Connection, the Server URL, Username and Password fields each sit on their own row with their label above, on desktop and mobile. ([#278](https://github.com/Kazo-ca/Os/pull/278))
- **File Explorer: network drives aligned left and errors in a message box.** Network drive names are aligned left and stay on one line, with a horizontal scroll bar when they are too long. Errors, such as a file no application can open, appear in an error message box instead of red text in the window. ([#277](https://github.com/Kazo-ca/Os/pull/277))
- **Dropping a file outside a drop zone.** Dropping a file outside every drop zone no longer opens it in the browser. ([#275](https://github.com/Kazo-ca/Os/pull/275), [0185-file-explorer-improvements.md](doc/en/wasm/dev/adr/0185-file-explorer-improvements.md))

- **Title bar of maximized and snapped windows.** The buttons of a maximized or snapped window stay clickable, dragging the title bar restores the window, and a double-click maximizes it. ([#222](https://github.com/Kazo-ca/Os/pull/222), [0177-title-bar-of-maximized-and-snapped-windows.md](doc/en/wasm/dev/adr/0177-title-bar-of-maximized-and-snapped-windows.md))
- **A screen closed by hand is forgotten even after a quick reload.** Restoring the screens of the last session no longer rewrites screens.config with the values it already holds, so closing a screen right after is saved at once. The icon packs and sound themes installed in the background are recorded in /var/lib/hackeros/installed: later boots skip them, and an install cut by a reload completes at the next boot. ([screen-service.md](doc/en/wasm/dev/screen-service.md), [icon-packs.md](doc/en/wasm/dev/icon-packs.md))
- **The desktop opens faster after the first sign-in.** The Néon icon pack is now copied to /usr/share/icons in the background once the session is open, instead of making the first sign-in wait about ten seconds. ([icon-packs.md](doc/en/wasm/dev/icon-packs.md))
